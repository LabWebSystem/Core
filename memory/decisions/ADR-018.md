# ADR-018: mDNS公開名を単一DNSラベルへ平坦化する

Status: ACCEPTED
Context: WindowsのmDNS resolverは3ラベル以上の公開名を解決できない。従来の`<appName>.<base-domain>`形式は、ベースドメインが`example.local`の場合に3ラベルとなり、アプリ、Dashboard、APIへアクセスできない。
Decision: Avahiをホストネットワーク上で実行し、BackendがSQLiteから生成するhostsを静的mDNSレコードとして広告する方式は維持する。公開ホスト名は、appNameとベースドメインの末尾ラベルより前をハイフン連結し、末尾ラベルとの間だけドットを置く。例: `app`と`lab.local`は`app-lab.local`、`app`と`one.two.local`は`app-one-two.local`。アプリ、Dashboard、APIに同じ命名規則を適用する。appNameはAPIとSQLiteで`appName` / `app_name`とし、既存DBの値を保持して列名をmigrationで変更する。生成するDNSラベルは63文字以内とし、APIとDashboardのシステム名は通常アプリ名として予約する。
Rejected: `<appName>.<base-domain>`を継続すること。WindowsのmDNS resolverで3ラベル以上の名前が解決できないため。DNSラベルを自動短縮すること。名前の一意性と予測可能性を損なうため。
Consequence: Dashboard、Backend API、アプリのhosts、Caddy route、画面に表示するアプリURLは同じ公開名生成規則を使う。既存環境はDBのアプリ名とデータを保持し、Backend再起動時に派生設定を新しいURLへ切り替える。旧ドット区切りURLは継続提供しない。ベースドメイン変更、80/tcpとUDP 5353の競合処理、mDNSを通さないVLANを越えた名前解決の非対応は従来どおりとする。
Related: ADR-002, ADR-016, ADR-017, CHG-096, SUP-003
CurrentValue: current
FutureRelevance: reusable
ValidityScope: LWSの`.local` / `.localhost`公開ホスト名とmDNS
