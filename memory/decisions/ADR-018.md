# ADR-018: GitHubとZIPからアプリを取り込む

Status: ACCEPTED
Context: GitHubで管理されていないComposeアプリや、LWS向けmanifestのないアプリもLAN内へ公開する必要がある。アプリsourceと利用者の公開先選択は未信頼である。
Decision: ホスト設定は`/etc/lws`、LWS管理データは`/var/lib/lws`へ集約し、Backend SQLiteをアプリ定義と望ましい状態の正本とする。Avahi用hosts、Caddyfile、LWS用Compose overrideは派生物とする。GitHubまたはZIPをBackendの一時領域へ取り込み、Composeと任意のmanifestを検査する。manifestがある場合は表示情報・公開先と任意のメインComposeを初期値とし、ない場合は利用者が指定する。公開先を推測せず、選択はSQLiteを正本とする。ZIPは展開時にpath、ファイル種別、重複、容量、ファイル数を検証し、直下または直下の単一フォルダをsource rootとする。登録後のZIP更新は再アップロードとし、失敗時は旧source・実行設定・公開状態を復元する。BackendはアプリComposeを直接書き換えず、公開serviceへのnetwork・固定labelをoverrideとして重ね、実効構成を検証して実行する。外部由来のbind mountを拒否し、永続データには名前付きvolumeを使用する。環境変数はBackendが管理し、sourceの`.env`は使用しない。Docker socketはBackendだけが使用する。
Rejected: ZIPを無検証で展開すること、公開serviceやportを推測すること、manifestを必須とすること、アプリComposeを直接書き換えること。
Consequence: Backendが取得・検査・永続化と実行を担当し、Dashboardは候補の確認と不足項目の入力を担当する。既存のCompose事前検査、edge network、LWS所有確認、設定レイヤーを維持する。ADR-005の公開サービスをmanifest指定に限定する部分は本判断に置き換える。
