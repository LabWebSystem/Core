# ADR-001: LWS配布とライフサイクルの基盤

Status: ACCEPTED
Context: LWS needs a reproducible installation and release path while component behavior is still mocked.
Decision: Keep `mise` as the local task entry point; publish LWS `.deb`/`.rpm` artifacts via GitHub Releases, mock images via GHCR workflows, and the SDK independently via GitHub Packages. Keep runtime lifecycle in the six-command `lwsctl` and use a Compose project plus LWS ownership labels for safe stop/rebuild operations.
Rejected: Starting containers from package installation, embedding images in packages, or allowing `lwsctl` to replace APT/DNF file ownership.
Consequence: `start` performs first configuration, package removal hooks stop the Compose project, and `uninstall --purge` is the only destructive data removal path.
Related: docs/LabWebSystem設計概要.md
CurrentValue: current
ValidityScope: LWS foundation distribution and lifecycle
