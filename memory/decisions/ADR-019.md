# ADR-019: GitHub ActionsをCore品質ゲートの実行正本とする

Status: ACCEPTED
Context: 品質ゲートの全体実行定義がローカルの逐次スクリプトとWorkflow起動設定に分かれ、手元の実行時間も長かった。Coreの検証・リリースをGitHub Actionsへ集約し、独立検証を別runnerで並列実行する。
Decision: GitHub Actionsの再利用可能な品質WorkflowをCoreの品質ゲート構成と依存関係の正本とする。各ジョブは既存の`mise` taskを呼び出す。通常のpushとpull requestはfast、手動検証とLWSリリースはfullを実行する。fast検証成功後、独立したQAを並列実行し、全品質ゲート成功後にだけイメージ公開へ進む。`mise run verify`はcleanで追跡先と一致するpush済みコミットをActionsへ送り、runを監視して結果artifactを取得する。イメージdigestがそろった後にpackageを一度だけ生成する。
Rejected: 同じ品質ゲートの項目一覧をローカル実行スクリプトと複数Workflowへ重複定義すること。公開を品質ゲートより先に実行すること。品質検証で作った非公開digest packageを、release用package生成より前に重複して作ること。
Consequence: `mise run verify`はGitHub CLI認証、cleanな作業ツリー、push済み追跡先を必要とする。未pushの変更は対象外で、ローカル実行結果ではなくActionsのsummary・artifactを確認する。QAまたはversion検証が失敗した場合、イメージ公開・package生成・Release公開は実行しない。既存`mise` taskは個々の検証実装の正本として維持する。
