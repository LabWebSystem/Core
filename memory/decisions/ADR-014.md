# ADR-014: 設定レイヤーとLWSデバイスプール

Status: ACCEPTED
Context: USB機器の`/dev` pathは接続ポートや再起動で変化する。一方、登録アプリはLWS外でも通常のComposeとして動作し、LWS独自のdevice記法やmanifest必須項目を要求してはならない。
Decision: Composeの標準`devices`を受理する。Composeにあるhost sourceは単体実行時のhintとし、LWS実行時にはDashboardで選んだLWSデバイスの現在pathへ生成overrideで置換する。LWSデバイスはimmutable ID、利用者名、stable identifier、現在path、接続状態で管理する。物理候補は`/dev`配下のchar/block device nodeから得る。通常表示はUSB serialを持つユーザーデバイスだけとし、管理者の明示操作時だけシステムデバイスを列挙する。名称はudevのvendor/modelを優先する。接続状態が不明・切断なら起動を拒否する。初回登録はcontainerを起動せず`CONFIGURING`へ遷移する。環境変数と各device bindingが設定済みになったアプリだけが開始できる。VolumeとNetworkはComposeとLWS所有labelを正本として集約表示するプールとし、外部resourceを共有・変更しない。
Rejected: `/dev/*`をmanifestで二重管理すること、Compose独自device構文、port pathをLWSデバイスIDとして保存すること、設定前の即時起動、外部Volume/Networkをプールへ取り込むこと。
Consequence: Backendはdevice bindingを永続化し、起動直前に現在pathを解決する。Dashboardはアプリ設定と3種類のリソースプールを表示する。利用者は意味上の機器選択を確認するが、LWSはhost pathの変動を吸収する。
