# ADR-005: アプリ単位のedge networkとCompose事前検査

Status: ACCEPTED
Context: 共有edge networkでは異なるアプリの同名Compose serviceが名前解決で衝突し、登録アプリ同士も直接通信できる。さらに未信頼なComposeを`docker compose config`へ渡す前に、外部ファイル参照を拒否する必要がある。LWSは少人数の信頼済みLANで使うため、初期実装に認証・認可を導入しない方針である。
Decision: 共有`lws-edge`は使用せず、アプリごとに`lws-app-<app-id>-edge` bridge networkを作成する。Caddyとmanifest指定の公開サービスだけを接続し、公開サービスには`lws-<app-id>` aliasを付与する。BackendはCompose設定展開前にsource treeのsymlinkと外部ファイル読込機能を拒否し、許可するpathがsource root配下であることを確認する。pathは丸めず、Google APIの標準エラー契約に沿う`PATH_OUTSIDE_PROJECT_ROOT`で拒否する。アプリ削除は登録解除と完全削除に分け、前者はvolumeと削除済み記録を保持し、後者だけがvolume削除後に記録を消す。管理HTTP APIは認証なしとし、到達可能なLAN端末を管理者として扱う。
Rejected: 全アプリを共有networkへ接続すること、Compose pathを書き換えて領域内へ丸めること、Compose正規化後だけに検査を行うこと、認証・認可を実装してデフォルト無効にすること、登録解除時にvolumeの所有記録を失うこと。
Consequence: Backendはアプリごとのnetwork作成、Caddyの動的接続と再調整、network alias、Compose事前検査、削除済み記録を実装する必要がある。Docker daemonのアドレスプールは想定network数を許容する運用設定が必要である。HTTP通信上のsecretの秘密性は保証しない。
