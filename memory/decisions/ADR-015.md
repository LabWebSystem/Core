# ADR-015: 層別テストを先行し、大きな境界だけE2Eで確認する

Status: ACCEPTED
Context: LWSではInfrastructure、Backend、Frontend、E2Eが重複して同じ動作を確認すると、テストが遅く複雑になる。一方、各層だけではDashboardからDockerまでの連携不具合を検出できない。
Decision: Infrastructure、Backend、Frontendの小さな機能追加、バグ修正、品質評価では、実装前に対象層のテストを追加する。バグの再現テストは回帰テストとして残す。E2EはLWS全体の安定性・性能評価、大きな機能追加、複数コンポーネントの境界確認に限定して追加する。
Rejected: すべての変更をE2Eで確認すること。小さな層内変更を実環境へ接続して確認すること。内部テストの結果だけで未実装の受け入れシナリオを成功扱いにすること。
Consequence: 変更は原因に最も近いテストで先に固定する。E2Eは少数のシステムシナリオに集中し、専用Compose環境を使う。機能テストの正本は`docs/機能テストルール.md`とする。
Related: ADR-012, docs/機能テストルール.md
CurrentValue: current
FutureRelevance: reusable
ValidityScope: Infrastructure、Backend、Frontend、E2Eのテスト追加と品質ゲート
