# ADR-013: Backend集約の永続ログ収集・検索・配信

Status: ACCEPTED
Context: 現在の`:tailLogs`はDocker CLIの追尾出力をアプリ単位で直接SSE配信するため、Backend再起動後の参照、Operation出力、LWS基盤ログ、再接続時の欠落防止、関連ログ検索を一貫して扱えない。LAN内の単一ホストLWSでは、Fluent Bit、Loki、イベントブローカーなどの新たな常駐基盤を増やさずに、既存のSQLiteとBackend内SSEでこれらを提供する必要がある。
Decision: Backend内の常駐`RuntimeMonitor`をログの収集器とし、Backendをログの正本とする。`RuntimeMonitor`はDocker公式Go SDK（API version negotiationを有効化した固定versionの`github.com/moby/moby/client`）で、現在存在するLWS所有containerのログと、以後のDocker event streamを継続監視する。監視対象は`com.labwebsystem.owner=lws`および現在のinstallation IDで所有確認できるcontainerだけとし、基盤container（backend、caddy、coredns、dashboard）と登録アプリのstdout/stderrを収集する。非TTYのstdout/stderr分離はSDKの`stdcopy`を使う。Docker CLIのログ出力を解析しない。

ログはSQLiteの`log_entries`に一種類の`LogEntry`として保存する。必須の識別・順序項目は`id`、opaqueな`cursor`、`occurredAt`、`level`、`component`、`message`とし、任意の関連項目として`applicationId`、`operationId`、`service`、`containerName`を持つ。`component`は`backend`、`caddy`、`coredns`、`dashboard`、`application`のいずれかとする。アプリcontainerはCompose projectとCompose service labelから`applicationId`と`service`を付与する。イベント、Dockerログ、Operation出力はいずれも同じ正規化・secretマスク・保存経路を通す。Git取得、Compose検証、起動、公開設定更新などのOperation実行器のstdout/stderrは逐次読取り、タスク名と`operationId`を付与して保存する。Backend自身の構造化ログには標準`log/slog`を用いる。

関連ログは別レコードとして複製しない。検索時にアプリID、Operation ID、Compose service、container、公開hostnameを根拠として関連性を導出する。`GET /applications/{application}/logEntries`は`view=task|application|related`、任意の`service`、RFC3339の`startAt`/`endAt`、opaqueな`cursor`、上限付き`limit`を受け、時刻・ID順のログ、次ページcursor、ライブ購読開始位置を返す。`GET /applications/{application}/logEntries:watch`は同じview/serviceと`after` cursorを受け、保存済みbackfillの後にSSEで新着を配信する。snapshotの上限cursorを先に確定し、その直後から新着を流すため、過去取得から購読開始の間に欠落・重複を発生させない。`task`はOperationに紐付くログ、`application`はアプリcontainerログ、`related`は対象アプリに確実に結び付けられたLWS本体ログだけを返す。

secretは保存前にマスクし、チャンク境界をまたぐ値も検出する。したがってSQLite、通常API、SSE、Backendの出力経路のいずれにも平文secretを残さない。不正な期間、cursor、serviceは400とし、別アプリのログは返さない。SSEも既存のHost/Origin制限を維持する。登録解除はログ履歴を保持し、完全削除（purge）時だけアプリに紐付く`log_entries`を外部キーcascadeで削除する。保持は定期削除し、初期値を「30日または100 MiBのうち先に到達した方」とする。容量超過時は古いログだけを削除し、他の永続状態を削除しない。

`lwsctl`の記録はDockerログへ混在させない。構造化したライフサイクル監査イベントとして、Backendが読める永続状態に別途記録する。
Rejected: Fluent Bit、Vector、Lokiなどのログ用container、Kafka/NATSなどのイベントブローカー、SSE専用外部ライブラリ、独自Dockerログ形式パーサ、Docker所有確認なしの全container監視、関連ログの重複保存、Docker streamへ`lwsctl`の監査記録を混在させること。
Consequence: OpenAPI、生成コード、SQLite migration、Docker abstraction、Operation executor、HTTP/SSE handler、保持ジョブ、既存`:tailLogs`の置換を段階的に変更する。migrationには時刻・cursor・application・operation・service・関連性検索のindexを含める。RuntimeMonitorはDocker stream切断時に再接続し、Backend起動時には既存LWS所有containerの監視から開始する。テストはfake Docker event/log sourceと固定clockによるGo単体テスト、Caddy経由Robot Framework API結合テスト、複数service fixtureを使う`mise run qa-lifecycle`の実Docker検証を行う。最終ゲートは`mise run verify qa`、`memadr check`、`memadr index`とする。

CurrentValue: current
FutureRelevance: reusable
ValidityScope: Backendのログ収集、永続化、検索、SSE、Operation出力、Docker監視
