# ADR-003: Backend APIのAIP準拠とOpenAPI契約

Status: ACCEPTED
Context: Backendは管理クライアント向けのHTTP/JSON APIを提供する。route、型、検証、clientを手書きで別々に定義すると、API契約の不整合が生じる。
Decision: Google AIPのresource-oriented design、標準メソッド、custom methodに従う。OpenAPI 3.1文書`backend/openapi.yaml`をAPI契約の正本とし、server interface、request/response型、入力検証、TypeScript clientをそこから生成する。現時点ではProtobuf、gRPC、HTTP transcodingを導入しない。
Rejected: HTTP APIとProtobufの二重契約、route・schema・clientの手書き重複、標準メソッドで表せる操作の独自endpoint化。
Consequence: API変更はOpenAPI文書と生成物を同時に更新し、CIで差分を検出する。時間のかかるアプリ操作はresourceベースcustom methodからOperation resourceを返す。
Related: ADR-002, docs/Backend仕様書.md
CurrentValue: current
FutureRelevance: watch
ValidityScope: Backend HTTP API
