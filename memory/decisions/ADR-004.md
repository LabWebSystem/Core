# ADR-004: Backendの応答性、SSE、およびOperation実行

Status: ACCEPTED
Context: LWSの管理操作はGit取得、build、Docker操作を含み、完了待ちや重複実行は管理クライアントの応答性と信頼性を下げる。ログは継続的に配信する必要があるが、通常のresource APIを独自の双方向プロトコルへ置換する必要はない。
Decision: HTTP/1.1 REST/JSONを正本APIとし、変更は永続化済みOperationを即時返却する。Operation状態とログはSSEで配信する。WebSocketは将来同じイベントenvelopeを使って追加できるが、初期実装では使用しない。同一app-idはOperationを直列化し、同じrequestIdの再送は同じOperationを返す。異なるapp-idは上限2のworker poolで並列実行する。Google SREのSLI、SLO、error budgetを28日rolling windowで測定する。
Rejected: 全APIのWebSocket化、WebSocketを操作の正本にすること、長時間操作のHTTP完了待ち、Backend全体の単一Operation直列化、無制限なログbuffer。
Consequence: HTTP APIは切断後の復旧とOpenAPI生成の正本を維持する。SSEは補助的な通知であり、欠損時はHTTP再取得で回復する。実装はrequestId、event ID、短期Docker状態snapshot、bounded queueを持つ必要がある。
Related: ADR-003, docs/Backend仕様書.md
CurrentValue: current
FutureRelevance: watch
ValidityScope: Backend API、Operation、リアルタイム通知
