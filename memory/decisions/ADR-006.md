# ADR-006: Backend実装技術スタック

Status: ACCEPTED
Context: LWSは既にGo 1.26の`lwsctl`とDocker Composeによる配布基盤を持つ。BackendにはOpenAPI 3.1からの契約生成、SQLite永続化、Docker操作、未信頼Composeの事前検査が必要であるが、単一ホストLAN用途に外部基盤を増やす必要はない。
Decision: BackendはGo 1.26と標準`net/http`で実装する。OpenAPI 3.1を正本とし、固定versionの`oapi-codegen`とOpenAPI request validation middlewareを使用する。SQLiteは`database/sql`とCGO不要の`modernc.org/sqlite`を使い、SQL migrationを`go:embed`で同梱する。Docker Engine Go SDKはDocker resource操作に、`docker compose`および`git` CLIはargv形式の外部実行に使う。Composeとmanifestの事前検査は`gopkg.in/yaml.v3`のNode ASTで実装する。非同期OperationはSQLiteとBackend内worker poolで処理する。
Rejected: Go以外のBackend言語、Web framework、ORM、Redis、メッセージキュー、外部job基盤、Kubernetes、Docker Compose意味の独自実装、管理API clientを外部アプリ向けSDKへ混在させること。
Consequence: Backend実行イメージには`git`、Docker CLI、Docker Compose pluginが必要であり、distrolessにはしない。依存versionとコード生成器は固定し、更新は生成物と契約テストを伴う。Docker socketの強い権限は技術選定によって軽減されないため、既存の入力検証と所有確認を維持する。
Related: ADR-002, ADR-003, ADR-004, ADR-005, docs/Infrastructure仕様書.md, docs/Backend仕様書.md
CurrentValue: current
FutureRelevance: watch
ValidityScope: BackendとInfrastructureの初期実装技術
