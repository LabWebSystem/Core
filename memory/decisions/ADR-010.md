# ADR-010: miseを品質ゲートの正本とする

Status: ACCEPTED
Context: Core、SDK、Dashboard、QAの検証が別々のWorkflowとRobotの代理実行へ分散していた。SDKは通常CIに参加せず、Dashboardはリリース時だけbuildされ、CIでは`mise run test`と個別targetが重複実行されていた。
Decision: 全コンポーネントの品質検証は`mise` taskへ定義する。通常CIは`mise run verify`、LWSリリース前は`mise run verify-release`、SDKリリースは`mise run test-sdk`を呼ぶ。各コンポーネントは内部テストを所有し、QAは実環境の利用者境界を検証する。WorkflowとQAの責務境界はBash構造検査で固定する。
Rejected: GitHub Actionsへコンポーネントごとのtest jobを追加し続けること。RobotからGo・Shell・npmの内部テストを再実行して受け入れテストとして成功扱いにすること。構造検査をRobot Frameworkで実装すること。
Consequence: コンポーネント追加時は対象コンポーネントの検証taskを`mise`へ参加させる。未実装の実環境QAは`planned`として扱い、内部テストの成功でGREENにしない。release用のdigest注入パッケージ化は、品質検証後のrelease workflowに残す。
Related: ADR-009, CHG-012, CHG-045, CHG-052, CHG-053, SUP-001, docs/品質ゲート統合実装計画.md
CurrentValue: current
FutureRelevance: reusable
ValidityScope: LWSモノレポの品質ゲート、CI、リリース、受け入れテスト
