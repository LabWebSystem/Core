# ADR-016: Avahiコンテナで`.local` mDNSだけを提供する

Status: ACCEPTED
Context: LWSはHTTP Reverse ProxyとLAN端末からの名前解決を提供する。利用者はベースドメインに`.local`を選び、ルーターDNSやLWSの通常DNS機能を必要としない。CoreDNSをmDNS用に改造して53番ポートで動かすと、通常DNSまで提供する印象と既存DNSとの競合が生じる。
Decision: LWSはAvahiコンテナをホストネットワークで動かし、BackendがSQLiteから生成した`hosts`を静的mDNS名として広告する。公開名は`api.<base-domain>`、`dashboard.<base-domain>`、各アプリ名とする。`lwsctl start`は`.local`で終わるbase domainを受け付け、ホストの80/tcpとUDP 5353を確認する。5353が使用中ならLWS起動を失敗させ、既存のmDNSサービスを停止・変更しない。CoreDNSと通常DNS転送はLWS runtimeから外す。
Rejected: CoreDNSを通常DNS兼mDNSサーバーとして維持すること。既存DNSサーバーとの役割競合と53番ポート公開が不要であり、本要件に追加価値がないため。AvahiとCoreDNSの両方を常時起動すること。DNS状態とmDNS状態を二重管理するため。
Consequence: 同一LAN上でmDNSに対応する端末は、ルーターDNS変更なしでLWS名を解決できる。通常DNSしか使わない端末や、mDNSを通さないVLANを越えた名前解決は対象外とする。通常DNSやクロスVLAN解決が要件になった場合は別の設計判断を行う。
Related: ADR-002, ADR-013, CHG-094, SUP-002
CurrentValue: current
FutureRelevance: reusable
ValidityScope: LWSの`.local`名前解決とmDNS実行環境
