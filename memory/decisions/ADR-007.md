# ADR-007: purge、原子性、起動時Docker再調整の方針

Status: ACCEPTED
Context: フェーズ4で、LWS本体とアプリのDocker resource削除、Backend再起動後の動的edge network接続、失敗時の状態整合性を明確にする必要がある。
Decision: `lwsctl down --purge`はCLI確認または`--force`後に、LWSの全アプリと本体を停止し、現在のinstallation IDとLWS所有labelで識別できるcontainer、network、named volume、設定、状態だけを削除する。外部Docker resourceは対象にしない。アプリpurge APIは`UNREGISTERED`かつ`confirm:true`だけを受け付ける。登録解除はsource、runtime、設定、named volume、DB記録を保持した`UNREGISTERED`へ遷移し、再登録で復帰できる。完全削除だけがそれらとDB記録を物理削除する。Docker操作はDBトランザクションとみなさず、変更順序、補償処理、冪等な再実行で原子性を守る。Backend起動時はSQLiteのACTIVEかつRUNNINGなアプリを正本として、edge networkとCaddy接続をDocker実状態へ再調整する。管理API clientはDashboard以降の責務とし、Docker操作はDocker CLIを継続利用する。
Rejected: `docker system prune`、installation IDを無視した削除、ACTIVEアプリの即時purge、Caddy接続状態のDB複製、Backend再起動時の無条件な全アプリ起動。
Consequence: lwsctlはCompose project以外のアプリresourceもlabelで限定して停止・削除する。BackendはCaddy起動待ちの再試行と、登録解除失敗時のACTIVE状態・公開経路復元を実装する。旧`config.env`は不足するinstallation IDと公開IPv4を生成してatomic renameで移行する。
Related: ADR-005, docs/Infrastructure仕様書.md, docs/Backend仕様書.md
CurrentValue: current
FutureRelevance: reusable
ValidityScope: フェーズ4以降のpurge、Docker再調整、失敗時復元、設定移行
