# ADR-011: Dashboardはデバッグルームから段階的に洗練する

Status: ACCEPTED
Context: Dashboardは未実装であり、見た目を先行させると未完成の機能や不十分な導線が隠れ、実運用に必要な操作を見落とすおそれがある。
Decision: Dashboardは、LWSが提供する全機能へアクセスできる簡素で非構造的な一画面のデバッグルームを最初に実装する。機能・状態表示・導線をここで検証し、後続の画面は機能を損なわない範囲で段階的に構造化・洗練する。画面制作はcode-firstを既定とし、採用するフロントエンドのライブラリ、アーキテクチャ、UIライブラリは実装開始時点で安定性と成熟度を評価して選ぶ。
Rejected: 完成した見た目を先行して作り、機能実装を後から当てはめること。機能と導線が確定する前にDashboardを複数画面や複雑な情報構造へ分割すること。
Consequence: 初期Dashboardは視覚的な完成度より、すべての機能へのアクセス、状態の可視化、操作の検証可能性を優先する。後続のUI改善では、デバッグルームで確認済みの機能・導線を後退させない。
Related: ADR-002, CHG-063
CurrentValue: current
FutureRelevance: reusable
ValidityScope: LWS Dashboardの実装順序、情報設計、UI技術選定
