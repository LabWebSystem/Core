# ADR-009: 機能受け入れテストをRobot Frameworkで分離する

Status: ACCEPTED
Context: LWSの機能テストはCLI、API、DNS、Docker、パッケージの利用者視点の操作を検証する。実装本体のテストコードや`scripts/test.sh`へ機能シナリオを集約すると、機能定義とテスト結果の対応が分散する。
Decision: 実装本体とは別の`qa/`でRobot Frameworkの受け入れテストを管理する。Robotの`.robot`ファイルを機能テストの正本とし、`mise run qa`を実行入口とする。PythonとRobot Frameworkの依存は`qa/pyproject.toml`と`qa/uv.lock`で固定し、ランタイム管理は`mise`へ委譲する。
Rejected: BackendのGoテストへ機能ワークフローを追加すること。既存の`scripts/test.sh`へ新しい機能シナリオを追加し続けること。機能テスト専用の実行器とレポート形式を独自実装すること。
Consequence: 既存のBackend・CLI・Infrastructureテストは当面維持し、機能ワークフローを段階的に`qa/`へ移行する。Robot Framework標準の実行結果と、静的HTML・JSONを生成する`robotframework-testdoc`を利用する。HTMLからMarkdownへの変換は、意味的に正しく変換できる既製手段が確認できるまで正本の生成経路に含めない。
