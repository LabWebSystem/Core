# ADR-002: InfrastructureとBackendの正本およびアプリ実行方式

Status: ACCEPTED
Context: LWSをLinuxパッケージとして導入するため、リポジトリ内の実行データに依存せず、アプリの永続データと生成設定を安全に管理する必要がある。同時に、登録アプリはLWS外でも通常のDocker Composeアプリとして実行できる必要がある。
Decision: ホスト設定は`/etc/lws`、LWS管理データは`/var/lib/lws`へ集約する。Backend SQLiteをアプリ定義と望ましい状態の正本とし、Caddyfile、CoreDNS用hosts、最小のLWS用Compose overrideを派生物として生成する。登録アプリはGitHub HTTPSリポジトリrootの`compose.yaml`と厳格な`lws.manifest.yaml`を必須とする。manifestは表示情報と単一の公開サービスを明示する。BackendはアプリComposeを書換えず、manifest指定サービスへのnetwork・固定label追加だけをoverrideとして重ね、Compose CLIが正規化した実効構成を検証して実行する。外部リポジトリ由来のbind mountは拒否し、永続データは名前付きvolumeだけに置く。環境変数の値はBackendが管理し、リポジトリの`.env`は使用しない。BackendだけがDocker socketを利用する。
Rejected: LWS専用の単一サービスCompose生成、公開サービスの推測、任意Composeの書換え、外部リポジトリ由来のbind mount、固定IP、独自DNSプロトコル実装、Backend以外へのDocker socket付与。
Consequence: アプリは単体でもDocker Composeで実行できる。LWSは安全性検証、名前解決、Reverse Proxy、固定project名、所有確認を追加する。通常`down`は設定・LWS管理データ・LWS所有volumeを残し、`down --purge`だけが削除する。
