# ADR-008: Infrastructure・Backend開発フェーズの現状

Status: ACCEPTED
Context: InfrastructureとBackendの実装をフェーズ単位で進めており、完了済みの範囲、現在の受け入れ基準、次に実装すべき範囲を一つの判断基準として残す必要がある。
Decision: フェーズ0〜3は完了とする。フェーズ4は、SQLiteを正本としたDNS・Reverse Proxy反映、app単位のedge network再調整、登録解除・再登録・purge、所有resource限定削除、原子性と失敗時復元、旧config.env移行まで実装済みであり、主要な単体・HTTP・Docker境界・実Docker統合テストを受け入れ済みとする。次の実装対象はフェーズ5とし、Operation状態SSEの再接続・欠損回復、コンテナログSSE、低速購読者の隔離、Backend再起動時の未完了Operation整理、DB障害・Docker timeout・ポート競合などの耐障害性を対象とする。
Rejected: フェーズ5の管理API clientをInfrastructureまたはBackendへ先行実装すること。Dashboardまたは将来の外部利用者がBackend API clientの責務を持つ。Docker操作方式をDocker Engine Go SDKへ変更すること。現行方針はDocker CLIである。
Consequence: フェーズ4の仕様変更を再開する場合は、登録解除後にsource・runtime・設定・named volume・DB記録を保持し、再登録で復帰できること、purgeは確認済みかつ所有確認済みresourceだけを物理削除することを維持する。フェーズ5では、SSEを正本状態の代替にせず、切断・欠損時はHTTP再取得で回復できる契約を維持する。フェーズ5完了まではP1要件のリアルタイム通知・耐障害性を未完了として扱う。
