# ADR-017: Dashboardを削除不可のシステムアプリとして実行する

Status: ACCEPTED
Context: Dashboardを基盤Compose serviceとして起動すると、登録アプリと実行・公開経路が分かれる。Dashboardの配布・起動・公開を通常のアプリ実行基盤へ揃えつつ、管理画面自体は削除されない必要がある。
Decision: Dashboard imageはLWSリリース成果物として維持し、Backend起動時にDashboardを`is_system`付きのアプリとして状態表へ登録する。通常アプリと同じCompose runtime、アプリ単位edge network、Caddy公開経路を使う。`dashboard` subdomainを予約し、システムアプリの削除・登録解除・設定変更をAPIで拒否し、DB triggerでも削除を拒否する。開始・停止は通常アプリと同様に許可する。開発時は同じシステムアプリのCompose sourceをVite用に生成する。
Rejected: Dashboardを基盤Compose serviceのまま残すこと。アプリ間の実行・公開経路の差を維持するため。Dashboardを通常の削除可能な登録アプリにすること。管理画面を失い、復旧手段も失うため。
Consequence: Backendは起動時にDashboardのアプリ状態とCompose sourceを確保し、通常のアプリ再調整で起動する。API/OpenAPIとDashboard UIはシステムアプリを区別し、削除操作を提供しない。リリースではDashboard imageを従来どおりBackend対応バージョンとともに配布する。
Related: ADR-002, ADR-012, ADR-013, ADR-016, CHG-095
CurrentValue: current
FutureRelevance: reusable
ValidityScope: Dashboardの登録、実行、公開、削除保護
