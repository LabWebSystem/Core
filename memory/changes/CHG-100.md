# CHG-100: 品質ゲートの重複作業を分離しキャッシュと工程計測を追加する

Status: SHIPPED
Area: CI / 品質ゲート
Reason: Core品質ゲートで高速工程と統合工程が同じmise taskを重複実行していた。また、隔離QAとZIP取り込みE2Eで時間の大きい工程が見えず、BackendのGo buildやPlaywright browserのキャッシュがジョブ間で利用されていなかった。
Change: `test fast`と`test full`を分け、GitHub Actionsの既存job順序とゲート項目を保ったまま統合工程の再実行をなくす。Go module/build cacheとPlaywright browser cacheを追加する。隔離QAではBackendとAvahiのイメージを先に一度だけbuildし、Composeから暗黙の再build・registry pullを禁止する。GitHub ActionsではBuildKit GHA cacheを使い、Backend root build contextの契約をテストする。各品質jobのActions実時間とゲート全体の経過時間をWorkflow summaryに表示し、工程別時間もログへ出力する。
FilesChanged: .github/workflows/ci.yml, .github/workflows/quality.yml, .github/workflows/release-lws.yml, .github/actions/go-cache, qa/resources/lifecycle.resource, scripts/build-test-image.sh, scripts/lint.sh, scripts/mise.lib.toml, scripts/prepare-lifecycle-compose.py, scripts/test-import-e2e.sh, scripts/test-quality-architecture.sh, scripts/test.sh, scripts/timing.sh
Verification: `mise run test fast`、`mise run test full`、`mise run lint`、`mise run test-import-e2e`、`mise tasks validate`、品質ゲート構造検査、Workflow YAML parseとActions時間summaryのfixture確認、`git diff --check`。変更前のActions run 41171674853（commit 9d2718b）は全体4m23s、静的検査57s、隔離Lifecycle QA 134s、Core統合116s。ローカルZIP E2Eは成功しPlaywright工程73秒を計測。`mise run qa-lifecycle`はホストの80/tcpまたは5353/udp使用中条件により3ケースがskipとなり、隔離起動は未検証。
Related: ADR-019, CHG-098, CHG-043, CHG-061
CurrentValue: current
FutureRelevance: reusable
ValidityScope: CoreのGitHub Actions品質ゲート、隔離ライフサイクルQA、ZIP取り込みE2E
