# CHG-079: 設定レイヤーとリソースプールを追加する

Status: SHIPPED
Reason: デバイスpathの変動を吸収しつつ、通常のCompose互換性を維持し、設定前の即時起動を防ぐため。
Change: Composeの`devices`を受理し、LWSデバイスプールのbindingから生成overrideへ現在の`/dev` pathを反映する。Backend imageへ`udevadm`を含め、ホストの`/dev`と`/run/udev`をread-onlyでmountして物理候補を検出する。通常はUSB由来のユーザーデバイスだけを表示する。`hidraw`など子nodeにUSB属性が継承されない環境では親USB pathも分類へ利用し、serialがないUSB機器も`usb topology`識別子として候補表示する。udevが返す`noserial`などのプレースホルダーは実シリアルとして扱わず、デバイスpath由来の識別子へフォールバックする。管理者が「システムデバイスを表示」を選ぶと、`/dev`配下のchar/block device nodeを列挙し、udevのvendor/modelまたは親USBのproductを人間向け名称として表示する。起動前とプール閲覧時に再検出するため、USB port変更後もcurrent pathを更新する。初回登録は`CONFIGURING`で停止し、必須環境変数とdevice bindingを満たした開始だけを許可する。Dashboardでは物理デバイスの登録、アプリごとのdevice選択、Volume・Network・Deviceプールを提供する。設定待ちから正常に同期できた場合は過去操作のエラー表示を消去し、設定待ち中は停止操作を表示しない。完全削除は設定待ちアプリも登録解除を経由して実行できる。システムデバイス表示からユーザーデバイス表示へ戻す際はモード別に候補を再取得し、前状態の候補を残さない。`/dev`走査で同一パスが重複しても候補を一件に正規化し、Dashboardの候補キーにはstable IDとpathを使う。
