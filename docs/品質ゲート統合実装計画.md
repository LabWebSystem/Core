# 品質ゲート仕様

品質ゲートの統合は完了しています。本書は実装計画ではなく、現在の実行契約を記録します。テストの詳細な責務は[機能テストルール](機能テストルール.md)を参照してください。

## 品質ゲート

| task | 目的 | 含む検証 |
|---|---|---|
| `verify` / `verify fast` | Actions上の高速検証 | 静的検査、Core高速テスト、SDK、Dashboard |
| `verify full` | Actions上の全品質ゲート | fast、Core統合テスト、自己完結QA、隔離ライフサイクルQA、QAドキュメント、ZIP取り込みのブラウザ・Docker結合テスト |
| `verify qa` / `verify release` | 互換指定 | `full`と同じ品質ゲート。package生成は含まず、release workflowだけがdigest付きで生成する |

ZIP取り込み結合テストには`caddy:2.10-alpine` imageを使用する。テストは一意のinstallation IDで隔離し、そのIDに属する資源と、テストが取得した未使用のimageだけを削除する。

## 責務

| 対象 | 所有する検証 |
|---|---|
| Core | Go、Shell、fixture、Infrastructureの内部・境界テスト |
| SDK | npmのtestとbuild |
| Dashboard | 静的検査のlint、test、build、Docker imageの検証 |
| QA | 利用者が観測するCLI、API、UI、公開経路をまたぐ受け入れシナリオ |
| 構造検査 | `mise`、Workflow、QAの責務境界 |

QAは`go test`、`npm test`、`scripts/test.sh`を実行して成功扱いにしません。未実装の受け入れシナリオは`planned`として管理し、対応するコンポーネントテストとは別に実環境を用いて検証します。

## 完了条件

- 品質Workflowを共通化し、通常CIはfast、手動検証とLWSリリースはfullを実行する。品質ゲートの実行基盤はGitHub Actionsとする。
- `mise run verify [fast|full]`はpush済みコミットの共通品質Workflowを起動して監視し、結果artifactを`test/result/actions/<run-id>/`へ保存する。
- SDKとDashboardが通常CIの品質ゲートに参加する。
- 共通品質Workflowは既存の`mise` taskだけを呼び、独立した検証を別runnerで並列実行する。
- リリース品質ゲートからパッケージ生成を分離し、3つの公開image digest取得後のpackage jobで一度だけ生成する。
- Workflowに個別の`go test`、`npm test`、`npm run build`、`robot`、`scripts/test.sh`を書かない。
- `qa/`に内部テストを代理実行するキーワードがない。
- `mise run test architecture`が上記の構造を検査する。
