# 品質ゲート仕様

品質ゲートの統合は完了しています。本書は実装計画ではなく、現在の実行契約を記録します。テストの詳細な責務は[機能テストルール](機能テストルール.md)を参照してください。

## 品質ゲート

| task | 目的 | 含む検証 |
|---|---|---|
| `verify` / `verify fast` | 開発・通常CI用の高速検証 | 静的検査、Core高速テスト、SDK、Dashboard |
| `verify qa` | QAを含む統合検証 | fast、Core統合テスト、自己完結QA、隔離ライフサイクルQA、QAドキュメント |
| `verify release` | LWSリリース前の検証 | qa、パッケージ生成。digest注入はrelease workflowの責務 |

## 責務

| 対象 | 所有する検証 |
|---|---|
| Core | Go、Shell、fixture、Infrastructureの内部・境界テスト |
| SDK | npmのtestとbuild |
| Dashboard | lint、test、build、Docker imageの検証 |
| QA | 利用者が観測するCLI、API、UI、公開経路をまたぐ受け入れシナリオ |
| 構造検査 | `mise`、Workflow、QAの責務境界 |

QAは`go test`、`npm test`、`scripts/test.sh`を実行して成功扱いにしません。未実装の受け入れシナリオは`planned`として管理し、対応するコンポーネントテストとは別に実環境を用いて検証します。

## 完了条件

- 通常CIは`mise run verify`、LWSリリースは`mise run verify release`を実行する。
- `verify`は端末へ項目要約を出力し、全検証の結果と生ログを`test/result/YYYY-MM-DD-verify-result.md`へ保存する。
- SDKとDashboardが通常CIの品質ゲートに参加する。
- Workflowに個別の`go test`、`npm test`、`npm run build`、`robot`、`scripts/test.sh`を書かない。
- `qa/`に内部テストを代理実行するキーワードがない。
- `mise run test architecture`が上記の構造を検査する。
