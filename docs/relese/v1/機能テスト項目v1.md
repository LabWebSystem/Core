# LWS 機能テスト項目 v1

## 1. 使い方

本書は、[機能定義書v1](機能定義書v1.md)の機能ワークフローを受け入れるためのテスト項目である。各項目は、未実装なら失敗するテストとして先に追加し、実装後にGREENへする。

低レベルの検証は既存の`U-*`、`H-*`、`D-*`、`I-*`テストへ対応付ける。機能テストはそれらを置き換えず、利用者の一連の操作と最終的な整合性を検証する。

## 2. 共通確認事項

すべての変更系テストで、必要に応じて次を確認する。

- 操作受付時にOperationが返る
- 最終OperationとApplicationの状態が一致する
- SQLite、Docker、生成設定の正本・派生関係が崩れない
- secret、ホスト絶対path、内部エラー詳細が利用者向け結果へ出ない
- LWS外のcontainer、network、volumeを操作しない
- 失敗後に再試行できる

## 3. テスト基盤検証項目

アプリ登録・公開機能は、fixtureを一時Git repositoryへ変換してから、GitHub形式URLのcloneを実行する。この前処理自体は利用者向け機能ではないが、機能テストの前提となるため、アプリ機能より先に検証する。

| ID | 対象 | 操作 | 期待結果 | レベル |
|---|---|---|---|---|
| TF-V1-001 | Git fixture基盤 | `test/apps/valid`から一時bare Git repositoryを作成する | `main` refを持つrepositoryが作成される | tooling |
| TF-V1-002 | Git fixture基盤 | GitHub形式URLをcloneする | fixtureの`compose.yaml`と`lws.manifest.yaml`を取得できる | tooling |
| TF-V1-003 | Git fixture基盤 | clone先のrefと内容を確認する | `main` refとfixtureの内容が一致する | tooling |
| TF-V1-004 | Git fixture基盤 | 一時Git repository、clone先、Git configを削除する | 作成した一時resourceだけが削除される | tooling |
| TF-V1-005 | Git fixture基盤 | 存在しないfixture、不正URL、既存出力先を指定する | 作成せず、部分的なresourceを残さず失敗する | tooling |

この項目は`FT-V1-*`の利用者向け機能テストとは分け、`TF-V1-*`として管理する。実装は`test/apps/`と`scripts/test-app-fixture.sh`を使用し、LWS本体へテスト専用のsource取得分岐を追加しない。

## 10. 実装時の対応表

機能テストを追加したら、実装ファイルと実行targetを記録する。最低限、次のtargetへ接続する。

現在の実装:

| 項目 | 実装 | 実行target |
|---|---|---|
| `TF-V1-001`〜`TF-V1-005` | `qa/suites/v1/fixture.robot`、`qa/resources/v1.resource`、`test/apps/` | `mise run qa`、`mise run qa-current` |
| `FT-V1-001`〜`FT-V1-003`、`FT-V1-007`〜`FT-V1-011` | `qa/suites/v1/cli.robot` | `mise run qa` |
| `FT-V1-004`〜`FT-V1-006` | `qa/suites/v1/lifecycle.robot`、`qa/resources/lifecycle.resource` | `mise run qa`、`mise run qa-lifecycle` |
| `FT-V1-020`〜`FT-V1-035` | `qa/suites/v1/application.robot` | `mise run qa` |
| `FT-V1-040`〜`FT-V1-045` | `qa/suites/v1/removal.robot` | `mise run qa` |
| `FT-V1-050`〜`FT-V1-058` | `qa/suites/v1/operation.robot` | `mise run qa` |
| `FT-V1-070`〜`FT-V1-073` | `qa/suites/v1/release.robot` | `mise run qa` |

Robot Frameworkの機能テストは、LWS本体の内部実装テストとは分離する。既存の`backend/feature_test.go`などは、機能テストを構成する低レベルのcomponent・境界テストとして維持する。

| 対象 | 正規入口 |
|---|---|
| CLI・install・package・release | `mise run test cli`、`installer`、`release` |
| Backend・DB・validator | `mise run test backend` |
| HTTP・OpenAPI・SSE契約 | `mise run test backend-http` |
| Git・Docker・Compose境界 | `mise run test backend-docker` |
| 実Compose・DNS・Caddy・network | `mise run test infrastructure` |

全項目が実装済みになった時点で、`mise run lint`、`mise run test`、`mise run package`を実行し、v1の完了条件を確認する。
